# ADR 002: Database & Persistence Strategy

## Status
Accepted

## Context
Open-ChatBot requires a persistent store for Character metadata, User profiles, Chat history, and State (Energy/Hunger/Relationship). The system needs to support high-read volume and complex relational queries while maintaining easy migration paths.

## Decision
We will use **SQLite** as the primary database for the initial release (Phase 1) due to its zero-config nature and file-based portability. However, all database interactions must use **SQLAlchemy ORM** to ensure a decoupled interface.

## Consequences
*   **Portability**: The entire database is a single file, simplifying local development and testing.
*   **Migration Path**: By using SQLAlchemy, we can migrate to **PostgreSQL** in Phase 2 (for multi-tenant horizontal scaling) with minimal code changes.
*   **Concurrency**: SQLite's write-locking may become a bottleneck at high scale; this is the primary trigger for the PostgreSQL migration.

## Alternatives Considered
*   **PostgreSQL (Native)**: Rejected for Phase 1 to reduce infrastructure complexity.
*   **MongoDB**: Rejected as the domain model (Users -> Characters -> Messages) is highly relational.
*   **Redis (Only)**: Rejected because we need ACID compliance for long-term character progression.
