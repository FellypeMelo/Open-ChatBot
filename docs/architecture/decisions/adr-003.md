# ADR 003: Local-First Inference Strategy (llama.cpp)

## Status
Accepted

## Context
The system must run locally for a single user, utilizing `llama.cpp` binaries for inference. This requires a bridge that manages process lifecycle, local resource constraints, and optimized context shifting.

## Decision
We will implement a **Local Inference Bridge** that interacts with `llama.cpp` via its HTTP server mode (`server.exe`). 

Key implementation details:
*   **Protocol**: HTTP/JSON for compatibility with existing OpenAI-like client libraries.
*   **Lifecycle Management**: The backend (`app/core/engine.py`) will manage the `llama.cpp` process or connect to a pre-running instance.
*   **Context Optimization**: Use `llama.cpp`'s `--slot-save-path` or similar state-saving features to minimize prompt re-processing for the single user.

## Consequences
*   **Performance**: Extremely low latency compared to cloud APIs, but limited by local GPU/CPU.
*   **Privacy**: 100% data sovereignty; no data leaves the local machine.
*   **Simplicity**: Multi-tenancy logic is removed; the system acts as a high-performance single-tenant workspace.

## Alternatives Considered
*   **Subprocess/CLI calls**: Rejected due to high overhead of reloading the model for every response.
*   **Python Bindings (llama-cpp-python)**: Considered, but `llama.cpp` binaries are preferred for easier updates and native performance monitoring.
