## Responsive layout for viewports < 768px, across all screens (Characters, Chat, Lorebook, Tags, all modals, sidebar)

**Current state:** The app has a real mobile foundation already in place. index.css uses `height: 100dvh` on html/body/#root (src/frontend/src/index.css:90) and `overflow: hidden` (line 97), so the shell itself never scrolls. App.tsx implements a proper drawer pattern: a backdrop overlay (App.tsx:532-537, md:hidden) plus a dedicated mobile top header with a hamburger (App.tsx:551-570). Sidebar.tsx:30-32 is a correct off-canvas drawer (`fixed md:sticky`, `-translate-x-full md:translate-x-0`, w-64). Most content grids degrade correctly to single column on mobile: CharactersView cards `grid-cols-1 md:grid-cols-2` (CharactersView.tsx:124), LorebookView entries (LorebookView.tsx:162), SettingsModal form fields `grid-cols-1 md:grid-cols-2` (SettingsModal.tsx:286), CharacterCreator general tab `md:grid-cols-[200px_1fr]` (CharacterCreator.tsx:253, stacks on mobile). ChatView already has the shipped mobile fixes: collapsible stats HUD (ChatView.tsx:217-233, `md:hidden` summary chip + `grid-cols-2 md:grid-cols-5`), tap-visible message/variant actions (`opacity-100 md:opacity-0 md:group-hover:opacity-100`, lines 439, 518, 574), and safe-area input padding `pb-[calc(1.5rem+env(safe-area-inset-bottom))]` (line 691). Modals use `p-sm md:p-md` and `w-full max-w-[...]` so they inset correctly; CharacterCreator caps height with `max-h-[90vh] overflow-y-auto` (line 204). The remaining failures are concentrated in a few header rows and one modal tab bar that were never given a mobile stacking/wrapping fallback, and because the shell is `overflow: hidden`, any horizontal overflow is clipped and becomes unreachable rather than scrollable. **2026-07-23 update:** all six gaps below (CharactersView/LorebookView header stacking, SettingsModal tab bar + panel scroll, ChatView footer wrap, TagManagementView search + CharacterCreator radio wrap) are now resolved — see the inline status line on each.

## Network resilience & connection UX over Wi-Fi/LAN

**Current state:** The app is served same-origin from FastAPI (src/backend/main.py) and reached from a phone at http://<pc-lan-ip>:8000. All frontend network calls are bare `fetch()` in src/frontend/src/services/api.ts with only `response.ok` checks and no timeout/abort/retry. The chat reply is a text/event-stream POST to /chat/stream (src/backend/api/chat.py:570) consumed by a manual ReadableStream reader loop in App.tsx handleStreamResponse (App.tsx:436-489). There is no reconnect layer, no offline detection, no request timeouts, no visibility/resume handling, and no cache headers on static assets. Icons and fonts are pulled from the Google Fonts CDN. Errors surface only as a 3s auto-dismiss toast. Grep across src confirms zero occurrences of AbortController, navigator.onLine, online/offline listeners, visibilitychange, EventSource, or Cache-Control.
