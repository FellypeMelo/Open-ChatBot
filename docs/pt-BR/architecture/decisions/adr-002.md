# ADR 002: Estratégia de Banco de Dados e Persistência

## Status
Aceito

## Contexto
O Open-ChatBot precisa de um armazenamento persistente para metadados de Personagens, perfis de Usuário, histórico de Chat e Estado (Energia/Fome/Relacionamento). O sistema precisa suportar alto volume de leitura e queries relacionais complexas mantendo caminhos de migração fáceis.

## Decisão
Vamos usar **SQLite** como o banco de dados principal para o lançamento inicial (Fase 1), devido à sua natureza zero-config e portabilidade baseada em arquivo. No entanto, todas as interações com o banco devem usar o **SQLAlchemy ORM** para garantir uma interface desacoplada.

## Consequências
*   **Portabilidade**: O banco de dados inteiro é um único arquivo, simplificando o desenvolvimento local e os testes.
*   **Caminho de Migração**: Usando o SQLAlchemy, podemos migrar para **PostgreSQL** na Fase 2 (para escalonamento horizontal multi-tenant) com mudanças mínimas de código.
*   **Concorrência**: O bloqueio de escrita do SQLite pode se tornar um gargalo em alta escala; este é o principal gatilho para a migração ao PostgreSQL.

## Alternativas Consideradas
*   **PostgreSQL (Nativo)**: Rejeitado para a Fase 1 para reduzir a complexidade de infraestrutura.
*   **MongoDB**: Rejeitado, pois o modelo de domínio (Users -> Characters -> Messages) é altamente relacional.
*   **Redis (Apenas)**: Rejeitado porque precisamos de conformidade ACID para a progressão de personagem de longo prazo.
