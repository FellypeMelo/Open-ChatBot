# ADR 003: Estratégia de Inferência Local-First (llama.cpp)

## Status
Aceito

## Contexto
O sistema precisa rodar localmente para um único usuário, utilizando os binários do `llama.cpp` para inferência. Isso exige uma ponte que gerencie o ciclo de vida do processo, as restrições de recursos locais e o context shifting otimizado.

## Decisão
Vamos implementar uma **Ponte de Inferência Local** que interage com o `llama.cpp` via seu modo de servidor HTTP (`server.exe`).

Detalhes-chave de implementação:
*   **Protocolo**: HTTP/JSON para compatibilidade com bibliotecas de cliente já existentes no estilo OpenAI.
*   **Gerenciamento de Ciclo de Vida**: O backend (`app/core/engine.py`) vai gerenciar o processo `llama.cpp` ou se conectar a uma instância já em execução.
*   **Otimização de Contexto**: Usar o `--slot-save-path` do `llama.cpp` ou features similares de salvamento de estado para minimizar o reprocessamento de prompt para o usuário único.

## Consequências
*   **Performance**: Latência extremamente baixa comparada a APIs em nuvem, mas limitada pela GPU/CPU local.
*   **Privacidade**: Soberania de dados de 100%; nenhum dado sai da máquina local.
*   **Simplicidade**: A lógica de multi-tenancy é removida; o sistema atua como um workspace single-tenant de alta performance.

## Alternativas Consideradas
*   **Chamadas via Subprocess/CLI**: Rejeitadas devido ao alto overhead de recarregar o modelo a cada resposta.
*   **Bindings Python (llama-cpp-python)**: Considerados, mas os binários do `llama.cpp` são preferidos por atualizações mais fáceis e monitoramento de performance nativo.
